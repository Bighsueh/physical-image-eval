## User Scenarios & Testing *(mandatory)*

### User Story 1 - 把唯讀來源匯成穩定的藍圖參考目錄 (Priority: P1)

操作者（系統／執行匯入的人）對唯讀來源目錄執行一次匯入。系統讀取來源，產出一份完整的參考目錄：8 個解剖區域、51 張藍圖、每張藍圖的整體 metadata（適應症、練習次數、溫馨小叮嚀）、每張藍圖的 4 個分格（步驟名、動作說明、時間提示、畫面視覺描述）、每張藍圖涵蓋的診斷、以及高風險旗標。匯入完成後，這份目錄即可作為後續審查流程的穩定參考資料；操作者得到一份成功報告，說明匯出了多少藍圖、各區域數量、以及診斷對帳結果。

**Why this priority**: 沒有這份參考目錄，審查者就沒有可審的對象，整個審查流程無法啟動。這是所有後續功能的資料地基，必須最先成立。

**Independent Test**: 對一份完整且正確的來源目錄執行匯入，驗證最終目錄恰含 51 張藍圖、區域分布為 S4 H4 E6 T8 P5 K7 L5 Y12、每張藍圖含 4 格且 metadata 非空、診斷對帳數字正確、高風險旗標正確標記。即使沒有任何審查域資料存在，本故事也能獨立驗證。

**Acceptance Scenarios**:

1. **Given** 一份完整且符合所有驗證不變量的唯讀來源目錄，**When** 操作者執行匯入，**Then** 系統產出恰 51 張藍圖，且區域分布為 S=4、H=4、E=6、T=8、P=5、K=7、L=5、Y=12。
2. **Given** 同上來源，**When** 匯入完成，**Then** 每張藍圖恰對應 4 個分格（圖1、圖2、圖3、圖4），且每格皆有動作說明。
3. **Given** 同上來源，**When** 匯入完成，**Then** 每張藍圖的 適應症、練習次數、溫馨小叮嚀 皆非空。
4. **Given** 同上來源，**When** 匯入完成，**Then** 高風險旗標恰標記於 S4、T8、P1、P4、P5、K2、K3、K5、L3 這 9 張藍圖，其餘藍圖皆非高風險。
5. **Given** 同上來源，**When** 匯入完成，**Then** 系統產出一份可讀的成功報告，列出藍圖總數、各區域數量、診斷對帳結果（已對應／轉介／通用處方模板）。

### User Story 2 - 驗證不變量失敗時 fail-fast、絕不寫入半套並產出可讀報告 (Priority: P1)

操作者對一份有缺陷的來源目錄（例如某張藍圖只解析出 3 格、缺少某項必填 metadata、診斷對帳數字對不上、或某張藍圖找不到對應圖檔）執行匯入。系統在任一驗證不變量失敗時立即停止，不持久化任何部分結果（不留半套目錄），並產出一份可讀的解析／驗證報告，清楚指出哪一條不變量在哪一張藍圖／哪一格失敗。來源目錄在整個過程中可被證明從未被寫入、改名、移動或刪除。

**Why this priority**: 半套或被污染的參考目錄會直接危及臨床審查的正確性與安全性；憲章亦明訂外部圖像唯讀、匯入失敗不得留半套。fail-fast 與唯讀保證與正確匯入同等重要，因此同為 P1。

**Independent Test**: 準備數份各自違反一條不變量的來源目錄，逐一執行匯入，驗證每次都整批失敗、目錄維持先前狀態（或為空）、報告明確指出失敗的不變量與位置，且來源目錄的內容與修改時間皆未改變。

**Acceptance Scenarios**:

1. **Given** 一張藍圖只解析出 3 格（或解析出 5 格），**When** 執行匯入，**Then** 匯入整批失敗（硬錯），且 0 筆藍圖被持久化。
2. **Given** 任一張藍圖的 適應症 或 練習次數 或 溫馨小叮嚀 為空，**When** 執行匯入，**Then** 匯入整批失敗，且報告指出該藍圖與缺漏的欄位。
3. **Given** 任一格的 動作說明 為空，**When** 執行匯入，**Then** 匯入整批失敗，且報告指出該藍圖與該格序號。
4. **Given** 某張藍圖找不到對應的單一圖檔，或某圖檔找不到對應藍圖（雙向孤兒），**When** 執行匯入，**Then** 匯入整批失敗，且報告指出孤兒項目。
5. **Given** 診斷對帳數字對不上（總數不為 134、或「對應到藍圖」＋「轉介」不等於既定拆分 128＋6、或某「對應到藍圖」的診斷指向不存在的藍圖），**When** 執行匯入，**Then** 匯入整批失敗，且報告指出對帳差異。
6. **Given** 任一次失敗的匯入，**When** 匯入結束，**Then** 來源目錄的所有檔案內容與修改時間皆未被改動，可證明從未被寫入。
7. **Given** 先前已存在一份成功匯入的目錄，**When** 一次新的匯入因不變量失敗而中止，**Then** 既有目錄維持原本可用狀態，不被部分覆寫。

### User Story 3 - 來源更新後可冪等重跑並取得變更與報告 (Priority: P2)

來源目錄在某次更新後（例如修正了某張藍圖的文字、調整了某項診斷對應），操作者重新執行匯入。若來源內容與上次相同，重跑會得到等價的目錄（冪等，不產生重複或漂移）。若來源確有變更，系統以更新後的來源為準刷新目錄，並在報告中摘要本次相對上次的變更（新增／修改／移除了哪些藍圖、分格、診斷對應、或高風險旗標）。

**Why this priority**: 來源是會演進的參考資料，需支援重跑以反映更新；但首次成立目錄（US1）與安全保證（US2）優先，故列為 P2。

**Independent Test**: 對同一份未變更來源連續匯入兩次，驗證兩次產出的目錄等價；接著對一份有單點變更的來源重跑，驗證目錄正確反映變更且報告摘要該變更。

**Acceptance Scenarios**:

1. **Given** 一份已成功匯入過的來源且內容未變，**When** 再次執行匯入，**Then** 產出的目錄與上次等價（藍圖、分格、診斷對應、高風險旗標皆一致），無重複項。
2. **Given** 來源中某張藍圖的某項 metadata 文字被修正，**When** 重跑匯入，**Then** 目錄中該張藍圖反映新文字，其餘藍圖維持不變，報告摘要「修改了該藍圖」。
3. **Given** 來源中某項診斷的對應關係改變，**When** 重跑匯入，**Then** 目錄的診斷對照反映新對應，報告摘要該變更。
4. **Given** 重跑時更新後的來源違反任一不變量，**When** 執行匯入，**Then** 重跑整批失敗、不部分覆寫既有目錄，並產出失敗報告（與 US2 一致）。

### Edge Cases

- 來源中出現藍圖編號與既定 ID 規則（區域字母＋序號）不符、或重複的藍圖 ID：視為硬錯並於報告指出。
- 來源中存在不屬於任何已知區域（S/H/E/T/P/K/L/Y）的資料夾或檔案：視為硬錯或明確忽略，須於報告中說明處置，且不得使藍圖總數偏離 51。
- 某張藍圖對應到多於一個圖檔（非單一 2×2 圖）：視為硬錯（違反「每張恰對一個 PNG」）。
- 某張藍圖 涵蓋診斷 為 0 筆：允許（涵蓋診斷可為 0..n），不視為錯誤，但需確保不破壞 134 對帳。
- 診斷矩陣中標記為「轉介」的診斷不指向任何藍圖：屬正常，不算孤兒。標記為「已對應」或「通用處方模板」的診斷皆必須指向一張存在藍圖（通用處方模板指向 Y 系列藍圖）。
- 分格的 時間提示 或 畫面視覺描述 為空：不視為硬錯（僅 動作說明 為必填非空），但需於報告中以警示提示。
- 高風險集合與實際標記不一致（多標或漏標）：視為硬錯，必須恰等於 {S4, T8, P1, P4, P5, K2, K3, K5, L3}。
- 來源目錄不可讀取或不存在：匯入立即失敗並回報明確錯誤，不產生空目錄覆寫既有目錄。
- 匯入過程中途中斷（例如被終止）：不得留下半套目錄；下次匯入應能從乾淨狀態重建。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 以唯讀方式讀取來源目錄，且在匯入的任何階段都不得對來源目錄的任何檔案進行寫入、改名、移動或刪除。
- **FR-002**: 系統 MUST 從來源產出恰 51 張藍圖；數量不為 51 時視為硬錯並中止匯入。
- **FR-003**: 系統 MUST 將藍圖歸入 8 個解剖區域，且各區域藍圖數量 MUST 恰為 S=4、H=4、E=6、T=8、P=5、K=7、L=5、Y=12；任一區域數量不符即為硬錯。
- **FR-004**: 系統 MUST 為每張藍圖解析出恰 4 個分格（圖1、圖2、圖3、圖4）；分格缺少或多於 4 即為硬錯。
- **FR-005**: 系統 MUST 確保每張藍圖恰對應一個 2×2 四宮格圖像資產，且不存在雙向孤兒（無藍圖無對應圖像、亦無圖像無對應藍圖）。
- **FR-006**: 系統 MUST 驗證每張藍圖的 適應症、練習次數、溫馨小叮嚀 三項整體 metadata 皆非空；任一為空即為硬錯。
- **FR-007**: 系統 MUST 驗證每張藍圖的每一格 動作說明 非空；任一格 動作說明 為空即為硬錯。
- **FR-008**: 系統 MUST 對 134 個診斷進行對帳，且結果 MUST 符合來源總索引（`00_藍圖總索引與設計規範.md`）的權威拆分：128 筆「對應到藍圖」（含「同義合併已對應」與「通用處方模板涵蓋」兩種，兩者皆指向一張藍圖）＋ 6 筆「轉介」（不製圖、不指向藍圖）＝ 134；對帳總數或拆分不符即為硬錯。
- **FR-009**: 系統 MUST 驗證每一個非「轉介」診斷（即所有「對應到藍圖」者，含已對應與通用處方模板）都指向一張存在於目錄中的藍圖；指向不存在藍圖即為硬錯。
- **FR-010**: 系統 MUST 由區域與序號衍生並標記高風險旗標，且被標記為高風險的藍圖集合 MUST 恰等於 {S4, T8, P1, P4, P5, K2, K3, K5, L3}；多標或漏標即為硬錯。高風險集合 MUST 引用單一具名常數，不得在匯入中另行重複定義。
- **FR-011**: 系統 MUST 在任一驗證不變量失敗時採 fail-fast：立即中止匯入，且 0 筆藍圖、分格、診斷對應或旗標被持久化（不得留下半套目錄）。
- **FR-012**: 系統 MUST 在每次匯入（成功或失敗）結束時產出一份可讀的解析／驗證報告；失敗時報告 MUST 指出失敗的不變量及其位置（藍圖 ID、分格序號或診斷號），成功時報告 MUST 摘要藍圖總數、各區域數量與診斷對帳結果。
- **FR-013**: 系統 MUST 支援冪等重跑：對內容未變的同一份來源重複匯入，產出的目錄 MUST 等價（藍圖、分格、診斷對應、高風險旗標一致），且不產生重複項或內容漂移。
- **FR-014**: 系統 MUST 在來源確有變更時以更新後的來源為準刷新目錄，並在報告中摘要本次相對上次的變更（新增／修改／移除的藍圖、分格、診斷對應或旗標）。
- **FR-015**: 系統 MUST 在重跑因不變量失敗而中止時，保持既有可用目錄不被部分覆寫（既有目錄維持上一份成功匯入的狀態）。
- **FR-016**: 系統 MUST 為每張藍圖記錄其來源企劃出處的參照（可追溯回來源的對應描述），以利日後對帳與重跑變更比對。
- **FR-017**: 系統 MUST 將整個匯入視為一個全有或全無的批次：要嘛整份目錄成立、要嘛維持原狀，絕不存在介於兩者之間的部分狀態。
- **FR-018**: 系統 MUST 在來源目錄不可讀取或不存在時立即失敗並回報明確錯誤，且不得以空目錄覆寫任何既有目錄。
- **FR-019**: 目錄 MUST 為唯讀參考資料：本功能只由匯入／重跑產生目錄內容，匯入流程不得提供任何讓使用者手動建立或編輯藍圖、分格、診斷對應或旗標的途徑（維持目錄域與審查域分離）。
- **FR-020**: 目錄 MUST 保留每格「畫面視覺描述」為可供審查介面顯示之欄位；AI 產圖 prompt（aiPrompt）MUST 僅作內部欄位、不對審查者顯示（顯示與否的最終呈現由 003 規範）。
- **FR-021**: 報告 MUST 對「非硬錯但值得注意」的情況（如分格 時間提示 或 畫面視覺描述 為空、某藍圖涵蓋診斷為 0 筆）以警示層級提示，與導致中止的硬錯區分。
- **FR-022**: 系統 MUST 將藍圖 ID 依「區域字母＋序號」規則驗證唯一且合法；出現非法或重複 ID 即為硬錯。

### Key Entities *(include if feature involves data)*

- **AnatomicalRegion（解剖區域）**: 受審圖像的解剖分區。關鍵屬性：regionCode（S/H/E/T/P/K/L/Y 其一）、nameZh（區域中文名）、displayOrder（1..8 顯示順序）。一個區域 1 ──< 多張藍圖（依既定計數 S4 H4 E6 T8 P5 K7 L5 Y12）。
- **Blueprint（藍圖）**: 一張 2×2 四宮格運動衛教圖的參考單位。關鍵屬性：blueprintId（身分，依區域字母＋序號）、region（恰屬 1 個區域）、exerciseName（運動名）、indications（適應症）、frequency（練習次數）、gentleReminder（溫馨小叮嚀）、coveredDiagnoses（涵蓋診斷 0..n）、imageAsset（單一 2×2 圖像資產，唯讀）、sourceMarkdownRef（來源企劃出處參照）、version（版本，供重跑比對）、isHighRisk（由 ID 衍生的高風險旗標）、aiPrompt（AI 產圖 prompt，僅作內部欄位、不對審查者顯示）。一張藍圖 1 ──= 4 個分格。
- **Panel（分格）**: 藍圖內四宮格中的一格。關鍵屬性：panelIndex（1..4，對應圖1..圖4）、stepName（步驟名）、actionDescription（動作說明，必填非空）、timingHint（時間提示，選用）、visualDescription（畫面視覺描述，選用、保留為可供審查介面顯示之欄位）。從屬於恰一張藍圖。
- **Diagnosis（診斷）**: 診斷對照矩陣中的一筆診斷。關鍵屬性：diagnosisId（矩陣號）、nameZh（診斷中文名）、mappingKind（對應種類：已對應／通用處方模板／轉介）、mappedBlueprint（對應藍圖；「已對應」與「通用處方模板」皆必指向一張存在藍圖〔通用處方模板指向 Y 系列藍圖〕，「轉介」為 0／不指向）。全體診斷共 134 筆＝128「對應到藍圖」（已對應＋通用處方模板）＋ 6 轉介，依來源總索引（`00_藍圖總索引與設計規範.md`）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 對一份完整且正確的來源執行匯入後，目錄恰含 51 張藍圖，且全部 8 條核心不變量（51 張、區域分布、每張 4 格、單一圖像無孤兒、整體 metadata 非空、每格動作說明非空、134 診斷對帳、高風險集合）皆通過。
- **SC-002**: 任一單一不變量失敗的情境下，被持久化的部分資料恰為 0 筆（藍圖、分格、診斷對應、旗標皆為 0），目錄維持匯入前狀態。
- **SC-003**: 對內容相同的來源重跑匯入，兩次產出的目錄 100% 等價（藍圖、分格、診斷對應、高風險旗標逐項一致），且無任何重複項。
- **SC-004**: 每一次匯入結束都產出一份報告；在失敗情境中，報告能讓人在不查閱來源細節的情況下定位到失敗的不變量與其所在藍圖／分格／診斷（定位資訊命中率 100%）。
- **SC-005**: 經由比對來源目錄全部檔案於匯入前後的內容與修改時間，可證明任何一次匯入（成功或失敗）皆未對來源產生任何寫入（變更項目數為 0）。
- **SC-006**: 高風險旗標標記結果與既定集合 {S4, T8, P1, P4, P5, K2, K3, K5, L3} 完全一致（無多標、無漏標）。
- **SC-007**: 在來源發生單點變更後重跑，目錄正確反映該變更且其餘項目維持不變，報告準確摘要本次變更（變更摘要與實際差異一致）。
