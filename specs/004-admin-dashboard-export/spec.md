# Feature Specification: 管理員儀表板與匯出（Admin Dashboard & Export）

**Feature Branch**: `004-admin-dashboard-export`

**Created**: 2026-06-30

**Status**: Draft

**Input**: User description: "讓系統管理員以唯讀方式監看 51 張圖的審查完成度、各審查者進度、各圖覆蓋與判定分佈，並能匯出所有已提交審查結果（含每格細節與時間戳）以餵回修圖；管理員本人不審圖、也不得更動任何審查判定。"

## Clarifications

### Session 2026-06-30

- Q: 非在職（停用）審查者紀錄在儀表板統計中如何呈現？ → A: 匯出一律保留並標「非在職」；於完成度統計與在職比率分開呈現，不併入在職比率分子。
- Q: 匯出結構與多選編碼方式為何？ → A: 單列對應一組（審查者 × 圖）；多選集合以可解析的集合形式（分隔清單）編碼；高風險與「含需重做」以明確旗標欄位標示；確切檔案格式留待規劃階段。
- Q: 跨審查者歧見調解是否在 v1 範圍？ → A: v1 不提供調解／共識流程；儀表板僅呈現分歧（可鑽取對照），調解線下處理。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 監看整體完成度、審查者進度與各圖覆蓋分佈（Priority: P1）

系統管理員登入後進入儀表板，一眼看到整體審查完成度（所有在職審查者合計應審 vs 已提交），接著往下看到每位審查者的個別進度（已提交幾張 / 51、還缺哪些圖、最近一次提交是哪張、何時提交），以及每張圖被多少位審查者提交、還缺哪些審查者、該圖的 整體判定 分佈（通過 / 需小修 / 需重做 各幾筆）。管理員藉此判斷整個審查任務的進展，並決定要催哪位審查者、哪些圖即將可以進入修圖。

**Why this priority**：這是管理員存在於本工具的核心理由——掌握審查進度與結果分佈。沒有它，整個審查任務無法被治理；它本身即可獨立交付價值（即使匯出尚未做）。

**Independent Test**：建立數位審查者並讓他們對部分圖提交審查（保留部分為草稿、部分未動），開啟儀表板，驗證整體完成度、各審查者進度、未審清單、各圖覆蓋人數與 通過／需小修／需重做 分佈數字均正確，且草稿與未提交不被計入。

**Acceptance Scenarios**:

1. **Given** 共有 3 位在職審查者、合計應提交 153 筆（3 × 51），其中已提交 40 筆，**When** 管理員開啟儀表板，**Then** 整體完成度顯示 40 / 153 與對應百分比，且該百分比不把任何草稿或未動的圖計入分子。
2. **Given** 審查者甲已提交 12 張、其中最後一張為某圖且帶提交時間，**When** 管理員檢視甲的列，**Then** 顯示「12 / 51」、列出甲尚未提交的 39 張圖清單、並顯示甲最近一次提交的圖與時間。
3. **Given** 圖 S1 已被 2 位審查者提交、尚有 1 位未提交，**When** 管理員檢視 S1，**Then** 顯示「2 位已提交」、列出尚未提交 S1 的審查者，並顯示 S1 的 整體判定 分佈（例如 通過 1、需小修 1、需重做 0）。
4. **Given** 某審查者對某圖僅存草稿尚未提交，**When** 管理員檢視該審查者進度與該圖覆蓋，**Then** 該草稿不計入已提交張數、不計入該圖覆蓋人數、也不計入判定分佈。
5. **Given** 管理員想了解單一張圖的跨審查者意見，**When** 管理員從整體往下鑽取到該圖，**Then** 可看到逐位（已提交者）對該圖的 整體判定 與 適應症判定 對照，呈現是否存在分歧。

### User Story 2 - 匯出已提交審查結果以餵回修圖（Priority: P1）

系統管理員在審查累積到一定程度後，匯出所有已提交的審查結果，每筆對應一組（審查者 × 圖），內含 圖 ID／名稱／區域、整體判定、適應症判定與說明、四個分格（圖1..圖4）各自的 需要添加的警語（含警語－其它）、問題類型、問題說明，以及提交時間戳。管理員把這份匯出交給產圖團隊，據以逐張修正 AIGC 圖；草稿不得出現在匯出中。

**Why this priority**：匯出是把審查成果轉化為「修圖行動」的唯一橋樑，與監看並列為管理員的核心產出。沒有它，審查資料留在系統內無法驅動下游修圖。

**Independent Test**：在有已提交紀錄與草稿並存的狀態下執行匯出，驗證匯出含且僅含已提交紀錄（0 筆草稿）、每筆涵蓋全部規定欄位（含四格逐格細節與時間戳），且列舉值與審查表單逐字一致。

**Acceptance Scenarios**:

1. **Given** 系統內有 40 筆已提交與 7 筆草稿，**When** 管理員匯出，**Then** 匯出恰含 40 筆、不含任何草稿。
2. **Given** 某已提交紀錄整體判定為 需小修、適應症判定為 有疑慮 並含 適應症說明，且 圖2 有 需要添加的警語=骨鬆注意 與 問題類型=有錯字 與 問題說明，**When** 管理員匯出，**Then** 該筆完整呈現 圖 ID／名稱／區域、整體判定、適應症判定＋說明、圖1..圖4 各自的警語（含其它）／問題類型／問題說明、以及提交時間戳，無欄位遺漏。
3. **Given** 某已提交圖為「乾淨通過」（整體判定=通過、四格皆無警語且無問題類型），**When** 管理員匯出，**Then** 該筆仍出現，四格相關欄位以「空集合」明確表達而非缺漏。
4. **Given** 某 free text 欄位含特殊字元，**When** 管理員匯出，**Then** 其內容被安全處理，不破壞匯出結構、不造成注入。

### User Story 3 - 凸顯／篩選「需重做」與辨識高風險圖（Priority: P2）

系統管理員想優先處理問題最大的圖，於是篩選出「被至少 1 位審查者標為 需重做」的圖，並一眼辨識哪些是高風險圖（術後／骨折等禁忌須確認者），以便排定修圖優先順序與額外把關。

**Why this priority**：在 P1 的監看與匯出之上，提供優先級排序的便利。屬增益而非必要，故為 P2。

**Independent Test**：建立含 需重做 與非 需重做、含高風險與非高風險的圖集，套用篩選，驗證所有「≥1 位標 需重做」的圖被選出且無遺漏、無誤選，且高風險圖以非僅依顏色的方式被標示。

**Acceptance Scenarios**:

1. **Given** 圖 K3 被某審查者標為 需重做、圖 K1 無人標 需重做，**When** 管理員篩選「含需重做」，**Then** K3 被選出、K1 不被選出。
2. **Given** 高風險集合為 {S4, T8, P1, P4, P5, K2, K3, K5, L3}，**When** 管理員檢視任一圖，**Then** 屬於該集合者顯示可辨識的高風險標記，且該標記附文字／圖示而非僅以顏色表達。
3. **Given** 某高風險圖目前無人標 需重做，**When** 管理員檢視，**Then** 該圖仍被辨識為高風險（高風險與 需重做 為兩個獨立維度）。
4. **Given** 管理員想找「尚未達全覆蓋」的圖，**When** 管理員篩選「尚有審查者未提交」，**Then** 所有未被全部在職審查者提交的圖被選出。

---

### User Story 4 - 儀表板對審查資料唯讀（Priority: P2）

系統管理員在儀表板上瀏覽、篩選、匯出，但無論透過任何入口都無法新增、修改或刪除任何審查者的 整體判定、適應症判定、分格註記或草稿。管理員只觀察與匯出，不介入審查內容。

**Why this priority**：保障審查結果的可信度與角色分離；雖屬約束性需求而非新功能，但對治理至關重要，列為 P2 以明確驗證。

**Independent Test**：以管理員身分嘗試經由各種儀表板互動去更動任一審查紀錄，驗證不存在可成功改動審查內容的途徑，且審查資料在管理員操作前後位元相同。

**Acceptance Scenarios**:

1. **Given** 管理員正檢視某圖的判定分佈，**When** 管理員與儀表板任何元素互動，**Then** 不存在可變更該圖任何審查者判定或註記的操作。
2. **Given** 管理員執行匯出，**When** 匯出完成，**Then** 底層審查資料未被改動（匯出為純讀取投影）。
3. **Given** 審查者另在更新自己的草稿或已提交內容，**When** 管理員稍後重整儀表板，**Then** 儀表板反映審查者所做的最新變更，但變更來源僅為審查者本人、非管理員。

### Edge Cases

- 某審查者一張都尚未提交（進度顯示 0 / 51，未審清單為全部 51 張）。
- 某張圖目前 0 位審查者提交（覆蓋人數 0、判定分佈三項皆 0、無逐審查者明細）。
- 全部在職審查者皆完成全部 51 張（整體完成度 100%、每張圖達全覆蓋）。
- 同一張圖出現分歧（例如部分審查者 通過、部分 需重做）——需如實呈現而非合併為單一結論。
- 審查者被停用後，其先前已提交的紀錄一律保留於匯出並標記「非在職」，且於完成度統計與在職比率分開呈現、不併入在職比率分子（見 FR-016）。
- 系統尚無任何審查者帳號，或目錄域圖資料尚未就緒——儀表板與匯出須呈現合理空狀態，不報錯。
- free text 欄位（適應症說明、警語－其它、問題說明）含特殊字元或可能破壞匯出結構／注入的內容。
- 匯出當下有審查者正在編輯草稿——草稿一律不得進入匯出。
- 在職審查者人數變動（新增或停用）導致「應提交總數」改變，整體完成率須隨之正確更新。
- 高風險圖但目前 0 人標 需重做——仍須被辨識為高風險（兩維度獨立）。
- 同一審查者對同一圖只應有一筆已提交紀錄；不應因任何情況在統計或匯出中出現重複列。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 僅允許 系統管理員 角色存取管理員儀表板與匯出功能；審查者角色不得進入、查看或觸發其中任何部分。
- **FR-002**: 系統 MUST 在儀表板呈現整體審查完成度，以「已提交審查筆數 ÷ 應提交審查總數」表示，且分子與分母 MUST 採同一基準（僅在職審查者）：分母＝在職審查者人數 × 51，分子＝在職審查者的已提交筆數。停用（非在職）審查者的既有已提交紀錄 MUST NOT 併入此在職完成度比率（改於獨立「非在職」呈現，見 FR-016），以免比率超過 100% 或分子分母基準不一致。
- **FR-003**: 系統 MUST 為每位審查者顯示個別進度，含已提交張數（相對 51）與尚未提交的圖清單。
- **FR-004**: 系統 MUST 為每位審查者顯示近期活動，至少包含其最近一次提交對應的圖與提交時間。
- **FR-005**: 系統 MUST 為每張圖顯示覆蓋情況，包含已提交該圖的審查者人數，以及尚未提交該圖的審查者名單。
- **FR-006**: 系統 MUST 為每張圖顯示 整體判定 分佈（通過、需小修、需重做 各自筆數），且僅計入已提交紀錄。
- **FR-007**: 系統 MUST 將草稿（未提交）排除於所有完成度、覆蓋、判定分佈統計與匯出之外。
- **FR-008**: 系統 MUST 允許管理員從整體聚合鑽取到單一張圖，檢視該圖逐位已提交審查者的 整體判定 與 適應症判定 對照，以揭示跨審查者分歧。
- **FR-009**: 系統 MUST 標示每張圖是否屬於高風險集合 {S4, T8, P1, P4, P5, K2, K3, K5, L3}（以單一具名常數為準），且高風險狀態不得僅以顏色傳達，須並附文字或圖示。
- **FR-010**: 系統 MUST 允許管理員篩選／凸顯「被至少 1 位審查者標為 需重做」的圖。
- **FR-011**: 系統 MUST 允許管理員篩選／凸顯「尚有在職審查者未提交」（未達全覆蓋）的圖，並能識別已達全覆蓋的圖。
- **FR-012**: 系統 MUST 確保管理員儀表板與匯出對審查域資料完全唯讀；管理員不得新增、修改或刪除任何審查者的 整體判定、適應症判定、分格註記或草稿。
- **FR-013**: 系統 MUST 允許管理員匯出全部已提交審查結果，每筆對應一組（審查者 × 圖）。
- **FR-014**: 每筆匯出紀錄 MUST 至少包含：圖 ID、圖名稱、解剖區域、整體判定、適應症判定、適應症說明，以及 圖1、圖2、圖3、圖4 各自的 需要添加的警語（含 警語－其它）、問題類型、問題說明，與提交時間戳。
- **FR-015**: 匯出 MUST 僅含已提交紀錄、0 筆草稿；對「乾淨通過」的紀錄，其四格相關欄位 MUST 以明確的空集合表達而非缺漏。
- **FR-016**: 系統 MUST 將全部已提交紀錄（含停用審查者者）保留於匯出並標記「在職／非在職」；非在職紀錄於完成度統計 MUST 與在職完成度比率分開呈現，不得併入在職比率的分子，使分子分母基準一致（與 FR-002、FR-022 一致）。
- **FR-017**: 匯出 MUST 採單列對應一組（審查者 × 圖）的結構；多選集合（需要添加的警語、問題類型）MUST 以可解析的集合形式（如分隔清單）編碼；高風險與「含需重做」MUST 以明確旗標欄位標示。確切檔案格式（CSV／其他）留待規劃（plan）階段決定。
- **FR-018**: v1 MUST NOT 提供跨審查者調解／共識流程；跨審查者對同一張圖的判定分歧，儀表板 MUST 僅如實呈現（並可鑽取逐位審查者對照）而不自動合併，調解於線下處理。
- **FR-019**: 儀表板與匯出所使用的列舉值 MUST 與審查表單逐字一致（通過／需小修／需重做；合理／有疑慮；需要添加的警語：注意跌倒、需有專人幫助指導、骨鬆注意、心肺功能不全者注意、其它；問題類型：部位／主題錯誤、動作示範錯誤、文字說明錯誤、次數／時間不合理、缺安全提醒、有錯字）。
- **FR-020**: 系統 MUST 將所有 free text（適應症說明、警語－其它、問題說明）在儀表板顯示與匯出時視為不可信內容並安全處理，避免破壞匯出結構或造成注入。
- **FR-021**: 系統 MUST 在無任何已提交紀錄、或無任何審查者帳號、或目錄域圖資料尚未就緒時，於儀表板與匯出呈現合理空狀態而不報錯。
- **FR-022**: 系統 MUST 確保同一時點的整體完成度、各圖覆蓋與判定分佈三組數字彼此一致、互不矛盾。
- **FR-023**: 系統 MUST 確保每位審查者對每張圖在統計與匯出中至多出現一筆已提交紀錄，不得重複計列。
- **FR-024**: 系統 MUST 讓管理員的主要監看與篩選操作可純鍵盤完成，並確保所有狀態徽章（高風險、需重做、覆蓋）不僅以顏色傳達。

### Key Entities *(include if feature involves data)*

- **ReviewProgress（審查進度投影）**：衍生投影，不被儲存、不可變、永不寫回。由審查域與目錄域的唯讀資料即時推導，含三層：
  - 整體聚合——應提交審查總數、已提交審查總數、整體完成率。
  - 各審查者投影——審查者識別、在職狀態、已提交張數、尚未提交圖清單、最近一次提交的圖與時間。
  - 各圖投影——圖識別、是否高風險、已提交人數、尚未提交審查者名單、是否達全覆蓋、整體判定 分佈計數（通過／需小修／需重做）、是否含 需重做、以及逐位審查者的判定對照明細。
- **ExportRecord（匯出紀錄列）**：衍生投影，每筆對應一組已提交（審查者 × 圖）。屬性：圖 ID／名稱／解剖區域、整體判定、適應症判定、適應症說明、圖1..圖4 各自的 需要添加的警語（含警語－其它）／問題類型／問題說明、提交時間戳；並附審查者識別與在職／非在職狀態標記（依 FR-016）。唯讀，不改動來源資料。
- **Review（審查，唯讀引用）**：來自審查功能，提供每組（審查者 × 圖）的 整體判定、適應症判定、適應症說明、提交與否與提交時間戳。本功能僅讀取。
- **PanelReview（分格註記，唯讀引用）**：來自審查功能，提供 圖1..圖4 各格的 需要添加的警語、警語－其它、問題類型、問題說明。本功能僅讀取。
- **Account（帳號，唯讀引用）**：提供審查者識別與在職／停用狀態，用於計算應提交總數與標記紀錄歸屬。本功能僅讀取、不建立或修改。
- **Blueprint（藍圖／圖目錄，唯讀引用）**：來自目錄域，提供 51 張圖的 ID、名稱、解剖區域與高風險旗標，用於覆蓋與分佈的對齊與標示。本功能僅讀取。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理員可在儀表板識別出 100% 尚未達全覆蓋（尚有在職審查者未提交）的圖，無遺漏、無誤判。
- **SC-002**: 匯出涵蓋 100% 的已提交紀錄，且草稿混入筆數為 0。
- **SC-003**: 任一「被 ≥1 位審查者標為 需重做」的圖，可由管理員在 3 次以內互動被篩出或凸顯，且篩選結果之精確率與召回率皆為 100%。
- **SC-004**: 管理員可在 3 次以內互動，從整體完成度鑽取到任一單張圖的逐審查者判定明細。
- **SC-005**: 全部 9 張高風險圖在儀表板上皆有可辨識且非僅依顏色的標記，辨識正確率 100%。
- **SC-006**: 每筆匯出列含全部規定欄位（圖 ID／名稱／區域、整體判定、適應症判定＋說明、圖1..圖4 各自的警語／問題類型／問題說明、提交時間戳），欄位缺漏率為 0%。
- **SC-007**: 管理員無法經由儀表板或匯出改動任何審查紀錄；可成功改動審查內容的操作途徑數為 0，且匯出前後審查資料完全一致。
- **SC-008**: 同一時點的整體完成度、各圖覆蓋與判定分佈三組數字 100% 互相一致。
- **SC-009**: 在職審查者人數變動後，整體完成率於下次檢視時即反映新的應提交總數，無過期或矛盾數字。
- **SC-010**: 在「無任何已提交紀錄」與「無任何審查者帳號」兩種空狀態下，儀表板與匯出皆正常呈現、錯誤發生率為 0%。

## Assumptions

- 受審內容固定為 51 張 2×2 四宮格圖，分 8 解剖區域（S4、H4、E6、T8、P5、K7、L5、Y12），每張圖含 圖1..圖4 四個邏輯分格。
- 每位在職審查者的「應審範圍」即全部 51 張；管理員本人不審圖，故不計入應提交總數。
- 「已提交」定義為審查者對某圖完成正式提交；草稿一律不計入任何統計或匯出。
- 高風險圖集合 {S4, T8, P1, P4, P5, K2, K3, K5, L3} 由單一具名常數提供，目錄域與本功能共用，不重複定義。
- 同一審查者對同一圖至多一筆已提交紀錄。
- 高風險與「含需重做」為兩個彼此獨立的維度，可同時為真或同時為假。
- 儀表板以桌機／筆電為主要使用情境。
- v1 範圍僅止於呈現與匯出，不含跨審查者歧見的調解或回寫流程；儀表板僅呈現分歧，調解於線下處理（見 FR-018）。
- 匯出之消費者為「人」（產圖團隊據以修圖），非機器系統對接；確切檔案格式與結構於規劃階段決定。
- 匯出與儀表板均為審查域與目錄域之純讀取投影，永不改動來源資料。
